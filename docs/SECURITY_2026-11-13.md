# NewPro security hardening — 2026-11-13

Scope: `knowwssuz-byte/newpro`, Vercel project `newpro`, Supabase project `ylcipsfuojjvsqowbpol`. Baseline commit: `6039be3e6998c5d58244586f5604350863a8c751`.

## Changes

- Replace the browser-stored shared admin key with an opaque 256-bit session cookie. Cookies are HttpOnly, Secure in production, SameSite=Strict, host-only, and expire in 8 hours. Only an HMAC of the token is stored in a backend-only table. Logout deletes the session; rotating ADMIN_PANEL_KEY invalidates all existing sessions. Both admin screens use the same login mechanism. Legacy bearer keys and old dashboard cookies no longer authenticate.
- Require same-origin browser admin mutations. Rate-limit login to 10 attempts per IP per 15 minutes using an atomic PostgreSQL counter shared by all Vercel instances. General API ingress: 1,800/IP/minute; Telegram principal: 360/minute; sensitive player mutations: 60/minute; uploads: 30/IP/minute; media: 240/IP/minute. Trusted client IP is taken only from Vercel's overwritten forwarding header. Counters store HMAC identifiers, not raw IPs. A missing rate backend fails closed with 503. Shared-IP limits may need tuning using observed traffic.
- Enforce streaming body limits, JSON object validation, strict Telegram user IDs, duplicate-key rejection, signature verification and bounded session expiry in both verification paths.
- Add per-response nonce CSP with strict-dynamic, disabled inline script attributes and no production unsafe-eval. Preserve inline styles, permitted media and Telegram embedding. Use the Lottie SVG player without the expression evaluator; keep artwork, CSS and layout unchanged.
- Restrict the animation fetcher to the exact Supabase storage origin and bucket, disallow redirects, cap download/decompressed size, and add timeouts. Validate actual upload types and image dimensions. Rasterize permitted SVG uploads so active SVG documents are never published by these upload APIs. Sanitize server errors sent to clients.
- Revoke unnecessary public table, sequence and function privileges; preserve sanitized Arena event SELECT for realtime. Keep service-role backend access. Harden defaults for future objects. Add private session/rate tables and a cleanup schedule.
- Update Next.js to 16.4.6 and sharp to 0.35.5, refresh vulnerable transitive dependencies and pin a patched minimatch override. Deepmerge has no upstream patched release for GHSA-gcqx-w48m-w2h4: use the documented local MIT-licensed fork in `vendor/deepmerge`, blocking prototype keys in both operands. Add an npm audit gate in CI. Do not interpret an audit count of zero as proof of no vulnerabilities.

## Verification

- Behavioral tests exercise signed Telegram requests, hostile origins, chunked/oversized input, malformed JSON, upload validation, gzip limits, session expiry/key rotation/logout, cookie flags, old bearer rejection, brute-force blocking and fail-closed behavior.
- Isolated PostgreSQL executes the migration and checks atomic counters, concurrent calls, reset after expiry, anonymous denial, service-role access and future function privileges. Existing giveaway API/database flows remain covered.
- Production build and targeted security lint pass. Dependency audit reports zero known vulnerabilities with the local mitigation installed.
- Browser smoke additionally checks CSP violations and rejection of injected inline scripts. Run in GitHub CI: local browser launch is restricted by the execution environment.

## Limits and operations

This is a scoped source/dependency/database hardening pass, not a guarantee of invulnerability or a volumetric DDoS test. Credential strength, GitHub/Vercel/Supabase account MFA, credential compromise, hosting-level abuse controls and external Telegram/TON availability remain operational responsibilities. Existing 24-hour Telegram bearer data can still be replayed within its validity window if stolen; CSP, TLS, no-store responses and redacted errors reduce exposure but cannot make a compromised client trustworthy. Rate limiting is additional application protection, not an edge DDoS shield.

The existing no-policy RLS notices are intentional for backend-only tables. Never add broad client policies merely to remove those informational notices. Public Arena events contain only event ID, room ID and change timestamp. Existing balance/prize RPCs retain row-lock and owner checks. No production balance, gift or giveaway records are used for destructive tests.
